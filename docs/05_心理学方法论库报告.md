## 3 冻结取值

### 3.1 `entries.json` 单条 schema（11 key 逐字）

`id` / `name` / `family` / `principle` / `modes` / `trigger` / `injection{instruction,card_structure,rhythm}` / `evidence` / `reverse` / `conflict_priority`

- 顶层为**包裹对象** `{ version, count, entries[] }`（口径说明见 §6 待裁决 5）。
- `id` 固定 `PSY-001`~`PSY-079`（零填充 3 位），全库唯一，顺序 = id 升序。
- `modes` 为**条目级**适用档，∈ `quick`/`standard`/`deep`/`review`/`boost`；全档通用者 5 值全列（不使用「全档位」等非枚举词）。
- `injection.card_structure` 只引用 §4 的 16 个零件 `type`，逐条**归一化为零件 id**（如「复习卡 → 判题卡（必要时追加进度卡）」→ `review_card -> verdict_card(progress_card)`），不含动效/时长/曲线（R-T10）。
- `evidence` / `reverse` **全 79 条非空**（R-C3 / R-C4）；出处逐条锚定可复核的真实经典文献（作者 + 年份 + 文献/期刊/机制名），无一条使用「研究表明」类含糊话。
- `conflict_priority` 为整数 1~5（1 最优先），用于同族并列打破。

### 3.3 `retrieval-rules.json`（方案 B 的检索层）

- `index_line_format` = `id | 名称 | 适用档 | 一句话原理`（与 `INDEX.md` **同一格式、逐字一致**）。
- `injection_count` = `{"min": 3, "max": 8}`（硬约束 = D19 / C2.3）。
- `retrieval_input` = `["mode","skill","user_state","reverse_filter"]`（四类固定，不增删）。
- `selection_rules` = **6 条**（∈ 3~8）：① `mode` 硬过滤 → ② `trigger` 命中 → ③ 按该档族级优先级从高到低逐族取 → ④ `reverse` 命中整条剔除 → ⑤ 同族 ≤2 条、总数 3~8（不足 3 记 `psy_short`） → ⑥ 并列按 `conflict_priority` 升序打破。
- `reverse_filter_rules` = **3 条**（`reverse` 判定为真必须剔除，埋点记 `psy_filtered`，日志可证 = C2.5）。
- `conflict_priority_by_mode`（族级，左高右低；**5 档 × 6 族各一次**）：

| mode | 裁决优先级 |
|---|---|
| `quick` | 理解与建构 > 记忆与巩固 > 动机与情绪 > 习惯与节奏 > 练习与迁移 > 元认知 |
| `standard` | 理解与建构 > 练习与迁移 > 记忆与巩固 > 元认知 > 动机与情绪 > 习惯与节奏 |
| `deep` | 练习与迁移 > 元认知 > 理解与建构 > 记忆与巩固 > 动机与情绪 > 习惯与节奏 |
| `review` | 记忆与巩固 > 习惯与节奏 > 元认知 > 动机与情绪 > 理解与建构 > 练习与迁移 |
| `boost` | 练习与迁移 > 元认知 > 动机与情绪 > 记忆与巩固 > 理解与建构 > 习惯与节奏 |

> 经典冲突（验收 C2.4）：「降低认知负荷（理解与建构）」 vs 「制造必要难度（练习与迁移）」——
> `quick` 档在 ①位取「理解与建构」、②位才是「记忆与巩固」，而「练习与迁移」在末位；`deep`/`boost` 档把「练习与迁移」放在 ①位。输出不会前后矛盾。
